# v0.1.0-bootstrapping

The first campaign for this project: bootstrapping crypts-and-commits (CAC) itself, and dogfooding it to track that work. Covers standing up the `.sourcebook` for this repository - world summary, initial lore and regions - and the first encounters run through the CAC lifecycle, including fixing known issues discovered along the way (e.g. the Rich-markup body-rendering bug in `cac ... get` commands).

## Example

Analogous to a v0.1.0 release milestone: not a single ticket, but everything needed to get this repository's own sourcebook-driven workflow to a working, dogfooded state.

## Log

### Completed - 2026-07-25T15:05:25Z - John Hoff

Bootstrapped .sourcebook and drove all subsequent work on this repository through the cac CLI itself, achieving the campaign's primary goal: confidence that development can continue tool-first from here. Hardened the encounter and campaign lifecycles into code-enforced state machines (draft->reviewed->open->completed/abandoned, section-locking, single-open-campaign and open-encounter guards, dependency tracking via depends_on, independent-reviewer gating instead of self-review, and - as of this encounter - required postmortems on campaign completion/abandonment). Built a tiered retrieval and context-budget system (summary fields, cac prime, response truncation/paging) so the tool scales past small projects. Along the way fixed real papercuts surfaced by dogfooding itself: Rich markup silently eating bracketed text, non-ASCII output on Windows, and git-identity timestamping. One encounter (06-mcp-surface) was abandoned as premature, deferred until the skill/retrieval groundwork proved out in practice - which it has.
