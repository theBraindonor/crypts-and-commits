Build out the two aspirational regions (`demo-api`, `demo-ui`) into a working, read-only Q&A demo application - the significant gap this repository has carried since bootstrapping: neither package holds real code today (`demo-api` is a bare scaffold, `demo-ui` isn't even a PDM workspace member). This is the project's first non-`cac` codebase, and serves two purposes at once: a small, concrete demonstration of `cac` operating alongside non-`cac` application code in the same repository, and broader dogfooding of the framework's ability to carry lore/regions/campaigns for a multi-language, multi-package surface (Python FastAPI backend, Node/React frontend) rather than just its own single-package Python source.

Acceptance shape: a React application (`demo-ui`) that talks to an LLM agent running behind a FastAPI endpoint (`demo-api`). The agent answers questions with RAG grounded in this repository's own indexed sourcebook content (`index_search`) and packaged docs (`docs_list`/`docs_get`) - not by re-parsing markdown directly, consistent with `demo-api`'s existing region lore. It functions as a standalone Q&A surface, independent of any coding-assistant harness - a browser hitting a running server, not an agent session. It must have **no** ability to write to `.sourcebook` or anything else; read-only retrieval only, by construction, not just convention.

Encounters under this campaign will need to work out: the concrete LLM/agent orchestration approach (`demo-api`'s region lore currently assumes LangChain over swappable OpenAI/Anthropic models - confirm before building against that); how retrieval reaches both the search index and the docs surface without bypassing `cac`; how `demo-ui` gets scaffolded and wired into this repo's tooling given it isn't a PDM workspace member and there's no Node package manager or bundler chosen yet; and how the two packages are run/demoed together locally.
