Get `crypts-and-commits` ready for, and complete, its first public release: registering and publishing the `cac` Python package (currently unpublished - `packages/crypts-and-commits/pyproject.toml` is pinned at a static `0.1.0`, there's no `.github/` CI or publish workflow, and `docs/QUICKSTART.md` currently installs via a git URL specifically because no PyPI package exists yet).

Unlike the other two campaigns already drafted, this one's concrete task list isn't determined yet - it's explicitly a "is this ready to publish" punch-list that this campaign's own early encounters need to build by auditing the project's actual current state, not a pre-decided plan. Known candidate areas to survey (not a commitment to all of them): packaging/versioning strategy (the `v0.1.x` campaign-naming convention has already reached further than the package's pinned `0.1.0` - decide what, if anything, that means for the published version); a CI/publish workflow; license, metadata, and README accuracy for a public package page; and the deferred top-level public-facing documentation goal from `v0.1.5-generate-and-integrate-documentation`'s postmortem (CLAUDE.md/AGENTS.md authoring guidance) - explicitly called out there as work for "a future release-prep campaign," which this now is.

Successful completion of this campaign is the gate for the actual public release of the package - the release itself is the immediate next step once it completes, not part of the campaign's own scope.
