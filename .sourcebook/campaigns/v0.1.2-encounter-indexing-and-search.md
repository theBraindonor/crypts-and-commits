Provide indexing and search over encounters, closing the gap already flagged as a known limitation (see docs/encounter-search-design.md and the campaign-manager skill's note that no encounter search exists yet, only `cac encounter list` plus reading names). Covers choosing and implementing an indexing mechanism sufficient for an agent to find relevant past encounters - across campaigns, potentially - without linearly listing and reading everything, to assist in generating context for new work.

## Log

### Completed - 2026-07-28T00:29:48Z - John Hoff

Delivered full-text search over .sourcebook content, closing the gap flagged in docs/encounter-search-design.md. Built a SQLite FTS5 index (BM25-ranked, cross-campaign, includes completed/abandoned encounters) with a CLI search command and configurable snippet length; extended indexing beyond encounters to world/lore/region content (after backfilling created/updated stamps); exposed status and search over MCP; and finished by making the index self-maintaining - every cac-driven create/update/delete now incrementally patches the index via write_post/delete_post in frontmatter_utils, using short-lived connections and a busy timeout so concurrent CLI/MCP processes don't collide, with cac index rebuild retained only for the initial build and for resyncing changes made outside cac (e.g. a git pull). A late-discovered stale CLI help string describing the old rebuild-only model was also corrected. All open decisions from the original design doc (engine choice, indexing scope, cross-campaign search, ranking/snippet, git-ignored index location, write-path sync, CLI/MCP surface) ended up resolved. No open follow-ups identified.
