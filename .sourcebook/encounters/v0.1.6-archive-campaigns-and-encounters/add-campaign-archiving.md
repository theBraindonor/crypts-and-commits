## Requirements

- Add an `archived` boolean frontmatter field (default `false`) to both `campaign.md` and `encounter.md` — orthogonal to `status`, never replacing or erasing it. A `completed` campaign stays `completed` after archiving; only `archived` flips.
- New action: `campaign_archive(name)` (MCP tool) / `cac campaign archive <name>` (CLI). This is the **only** entry point — there is no standalone `encounter_archive`; encounters are archived only as a cascade of their parent campaign being archived, atomically, in the same call.
- Guard, checked in this order, each with its own named exception:
  1. The campaign must exist (`CampaignNotFoundError`, existing).
  2. The campaign's `status` must already be `completed` or `abandoned` (`CampaignNotTerminalError` - new). Archiving is not itself a status transition and does not require/accept a message.
  3. The campaign must not already be archived (`CampaignAlreadyArchivedError` - new).
  4. **Every** encounter under the campaign must also be `completed` or `abandoned` (`CampaignHasUnfinishedEncountersError` - new, naming each offending encounter and its status). This is a strictly broader check than `campaign_complete`/`campaign_abandon`'s existing open-encounter guard (which only blocks on `open`, letting `draft`/`reviewed` encounters slip through) - archiving closes that gap without changing `complete`/`abandon` themselves.
- On success: the campaign file moves from `.sourcebook/campaigns/<name>.md` to `.sourcebook/archive/campaigns/<name>.md`; every one of its encounter files moves from `.sourcebook/encounters/<campaign>/<name>.md` to `.sourcebook/archive/encounters/<campaign>/<name>.md` - a single `archive/` root mirroring the live `campaigns/`/`encounters/<campaign>/` layout exactly, one level down. Each moved file gets `archived: true` and a normal `stamp_updated` (`updated_by`/`updated_on`), nothing else - no `Log` entry, no status change.
- Index behavior: **unchanged** in this encounter. The move must use a raw filesystem write-to-new-path-then-unlink-old-path, *not* `frontmatter_utils.delete_post` on the old path - `delete_post` would call `search_index.sync_delete`, which `_classify()` still recognizes for the old `campaigns/`/`encounters/<campaign>/` path and would incorrectly purge the row. Writing to the new `archive/...` path through `frontmatter_utils.write_post` is safe and can be used as-is: `_classify()` doesn't recognize anything under `archive/`, so `sync_write` no-ops there, leaving the original row (indexed under the same `object_type`/`campaign`/`name`, keyed on name not path) untouched and still findable. This is a deliberate decision for this encounter - a later encounter is expected to make archived content excluded-by-default-but-searchable-on-request, per the GM's direction.
- Read access after archiving: `campaign_get`/`cac campaign get` and `encounter_get`/`cac encounter get` must keep working unchanged for an archived campaign/encounter - resolve the live location first, then the archive location, before raising not-found. The same fallback must apply to the path reported in a truncation notice (`campaign_path`/`encounter_path`), not just the read functions, or a truncated archived body would point somewhere the file no longer is.
- Explicitly **not** covered by this fallback: `campaign_list`, `encounter_list`, `encounter_order` remain live-directory-only, unchanged. Once a campaign is archived, calling `encounter_list`/`encounter_order` against it will report an empty result (a real behavior, not a bug) - archived content is inspectable one item at a time via `_get`, not via bulk listing, in this first encounter. This boundary must be stated explicitly in `docs/workflow.md`, not left implicit.
- No unarchive operation in this encounter (explicit GM decision) - noted as a follow-up in this campaign's remaining scope.
- `docs/workflow.md` (`templates/docs/workflow.md`) must be updated in the same change (`workflow-doc-source-of-truth`): `archived` added to both the Campaign and Encounter frontmatter bullet lists; a new row in the Campaign operation table (`Archive` | `campaign_archive` | `cac campaign archive`); a short new paragraph after the Campaign status-lifecycle table explaining what archiving is (an orthogonal flag, not a status), its guard (campaign and every encounter must already be terminal), what it moves, and the read/list asymmetry above; a note on the Encounter side that encounters are never archived standalone. "Explicit user gates" gets one sentence noting archiving isn't a fourth gate, consistent with how `pause`/`complete`/`abandon` aren't gated either.
- Both `campaign-manager` skill templates (`templates/skills/claude/campaign_manager/SKILL.md`, `templates/skills/codex/campaign_manager/SKILL.md`) must document the new tool in their "Campaigns" list and "Campaign Lifecycle" section, per `skills-authored-only-in-templates` - template files only, never `.claude/skills/`/`.agents/skills/` directly; the developer redeploys via `cac bootstrap init` after this encounter, not the agent.
- `cli-mcp-parity`: the one new CLI command (`cac campaign archive`) gets a matching MCP tool (`campaign_archive`) in the same change, plus `tests/mcp/test_server.py::test_all_domain_tools_are_registered` updated. No new domain module is needed (campaign.py/mcp/campaign.py already exist and are already registered) - only the tool-name set changes. Because there is deliberately no standalone `encounter_archive` command at either layer, no parity gap is created by that choice.
- `clean-tests-and-lint`: full `pdm run pytest -q` and `ruff check`/`format` gate before completion, as always.

## Rationale

This closes the first of this campaign's own open design questions in one encounter rather than several: layout, the "does archiving require every encounter to also be terminal" guard, and the tool surface. It deliberately does **not** close the index-consistency question - the GM's direction was explicit that this encounter should do nothing to the index (existing rows keep working because nothing calls `sync_delete` on the old path), and a subsequent encounter will add the excluded-by-default/searchable-on-request behavior described in the campaign body's original open question list.

Reusing `frontmatter_utils.write_post` for the new location and a raw `Path.unlink()` (not `delete_post`) for the old one is the load-bearing implementation detail that makes "index behavior unchanged" true without writing any index code in this encounter: `write_post`'s `sync_write` call is a no-op under `archive/` (unrecognized by `_classify()`), and skipping `delete_post` avoids the one code path that *would* otherwise delete the row. Getting this backwards (e.g. calling `delete_post` on the old path "to clean up") would silently break the "keep it searchable" decision - called out explicitly in the Requirements and Plan so it isn't lost during implementation.

The read-fallback for `campaign_get`/`encounter_get` (and the two path-for-truncation helpers) is scoped narrowly on purpose: it's a single shared "try live, then try archive" resolution added to the one function each module already funnels every existing-file lookup through (`_existing_campaign_path`, `_existing_encounter_path`), so every read caller benefits without duplicating logic - and since an archived campaign/encounter is always already terminal, none of the existing status-gated mutation paths (`update_campaign`, `encounter_open`, etc.) need any change: they already reject terminal-status objects regardless of where the file physically lives. Deliberately *not* extending the same fallback to `encounter_list`/`encounter_order`/`campaign_list` keeps this encounter's Plan bounded - those are enumeration over a directory, not a single lookup, and doing it properly (merging two directories' worth of encounters, keeping dependency-order results sane for a campaign that's half migrated) is a meaningfully bigger change than this encounter's stated scope. Documenting the resulting empty-list behavior in `docs/workflow.md` turns it into a known boundary instead of a silent gap.

No standalone `encounter_archive` was added (at either the CLI, MCP, or even core-module-public-API level beyond an internal helper) because the GM's direction was explicit: archiving enters only at the campaign level, cascading to encounters. This keeps `cli-mcp-parity`'s obligations narrow - one new command, one new tool - rather than inventing a second command surface nothing asked for.

`clean-tests-and-lint` (world-assigned) is satisfied by the Verification section. `cli-mcp-parity`, `console-best-practices`, `skills-authored-only-in-templates`, and `workflow-doc-source-of-truth` (all assigned to the `crypts-and-commits` region, where every changed file in this encounter lives) are each addressed directly above: parity is kept 1:1 for the single new command; the new CLI `console.print` calls are all CLI-authored strings (a name and a count), not stored content, so default markup is correct and no `markup=False` call is needed; skill changes land only in the two template files, with redeployment left to the developer; and `workflow.md` is updated in this same change to cover the new field, operation, and read/list asymmetry.

## Plan

1. **`core/config.py`**: add `ARCHIVE_DIR_NAME = "archive"` and `ARCHIVED_KEY = "archived"`.
2. **Templates** (`templates/sourcebook/campaign.md`, `templates/sourcebook/encounter.md`): add `archived: false` to each frontmatter block.
3. **`core/campaign.py`**:
   - Add `archived: bool` to the `Campaign` dataclass; populate in `_to_campaign` via `post.get(ARCHIVED_KEY, False)`.
   - Add `CampaignNotTerminalError`, `CampaignAlreadyArchivedError`, `CampaignHasUnfinishedEncountersError` (all `ValueError`), matching the existing exception docstring style.
   - Add `archive_campaign_dir(root) -> Path`, mirroring `campaign_dir`: `sourcebook_dir(root) / ARCHIVE_DIR_NAME / CAMPAIGN_DIR_NAME`.
   - Update `_existing_campaign_path`: if the live path doesn't exist, check `archive_campaign_dir(root) / f"{name}.md"` before raising `CampaignNotFoundError`.
   - Update `campaign_path(root, name)` to delegate to `_existing_campaign_path(root, name)` instead of unconditionally building the live-only path, so truncation-notice paths stay correct post-archive.
   - Add `archive_campaign(root, name) -> tuple[Campaign, list[str]]`: load the existing post; enforce the four guard checks in Requirements' order (terminal status, not-already-archived, then `encounter_core.unfinished_encounter_names(root, name)` empty); call `encounter_core.archive_encounters(root, name)` to move every encounter and collect their names; `stamp_updated` and set `archived: True` on the campaign post; `write_post` to `archive_campaign_dir(root) / f"{name}.md"` (creating the parent dir); `Path.unlink()` the old live campaign file directly (not `delete_post`); return `(_to_campaign(post, name), archived_encounter_names)`.
4. **`core/encounter.py`**:
   - Add `archived: bool` to the `Encounter` dataclass; populate in `_to_encounter`.
   - Add `_TERMINAL_STATUSES = frozenset({"completed", "abandoned"})` (module-local, mirroring `campaign.py`'s).
   - Add `archive_encounter_dir(root, campaign) -> Path`, mirroring `encounter_dir`: `sourcebook_dir(root) / ARCHIVE_DIR_NAME / ENCOUNTER_DIR_NAME / campaign`.
   - Update `_existing_encounter_path`: if the live path doesn't exist, check the archive location before raising `EncounterNotFoundError`.
   - Update `encounter_path(root, campaign, name)` to delegate to `_existing_encounter_path`, same reasoning as `campaign_path`.
   - Add `unfinished_encounter_names(root, campaign) -> list[tuple[str, str]]`: scan the *live* `encounter_dir(root, campaign)` only, return `(name, status)` for every encounter whose status isn't in `_TERMINAL_STATUSES`.
   - Add `archive_encounters(root, campaign) -> list[str]`: for every file in the live `encounter_dir(root, campaign)` (caller has already verified all are terminal), `stamp_updated`, set `archived: True`, `write_post` to the archive location (creating the parent dir), then `Path.unlink()` the old live file directly. Return the moved names, sorted.
5. **`cli/campaign.py`**: add `archive` command (`cac campaign archive <name>`, no `--message`/`--yes`), catching `CampaignNotFoundError` / `CampaignNotTerminalError` / `CampaignAlreadyArchivedError` / `CampaignHasUnfinishedEncountersError` / `GitIdentityError`, printing `"Archived {name} and {N} encounter(s)."`. Extend the Typer app's top-level `help=` string with one sentence on archiving.
6. **`mcp/campaign.py`**: add `"archived": campaign.archived` to `campaign_to_dict`. Add `campaign_archive(name) -> dict[str, Any]`, returning `{**campaign_to_dict(campaign), "archived_encounters": names}`.
7. **`mcp/encounter.py`**: add `"archived": encounter.archived` to `encounter_to_dict` for representational completeness (no new tool exercises it directly, since no standalone `encounter_archive` tool exists).
8. **`tests/mcp/test_server.py`**: extend `test_all_domain_tools_are_registered`'s expected tool-name set with `campaign_archive`.
9. **`templates/docs/workflow.md`**: updates listed in Requirements - frontmatter bullets (Campaign, Encounter), Campaign operation table row, new archiving-semantics paragraph after the Campaign status table (guard, what moves, read/list asymmetry), one-sentence Encounter-side note (no standalone archive), one sentence in "Explicit user gates" noting archiving isn't a fourth gate.
10. **`templates/skills/claude/campaign_manager/SKILL.md`** and **`templates/skills/codex/campaign_manager/SKILL.md`**: add a `campaign_archive(name)` bullet to "## Campaigns" (after the `campaign_delete` bullet, respecting each flavor's tool-name format - `mcp__crypts-and-commits__campaign_archive` vs. bare `campaign_archive`), and a new paragraph at the end of "## Campaign Lifecycle" describing `completed`/`abandoned` → archived, its guard, and the CLI fallback.
11. **Tests**:
    - `tests/core/test_campaign.py`: each guard's failure (not-terminal, already-archived, unfinished encounters - asserting the named/statused encounters in the message), a full successful archive (campaign file moved, `archived: True`, `status` unchanged, encounter files moved and flagged), `read_campaign`/`campaign_get` still resolving post-archive, `campaign_path` reporting the archive-location path post-archive, and `list_campaigns`/`list_campaigns_with_status` no longer including the archived campaign.
    - `tests/core/test_encounter.py`: `unfinished_encounter_names` returning the right set; `archive_encounters` moving files, setting the flag, and returning sorted names; `read_encounter`/`encounter_get`/`encounter_path` still resolving post-archive; `list_encounters`/`order_encounters` returning empty for an archived campaign (asserting the documented boundary, not just leaving it untested).
    - `tests/core/test_search_index.py` (or `test_campaign.py`, whichever already imports `search_index`): one explicit test proving a campaign's and an encounter's index rows survive `archive_campaign` unchanged - encoding this encounter's "don't touch the index" decision as a regression guard.
    - `tests/cli/test_campaign.py`, `tests/mcp/test_campaign.py`: the new `archive` command/tool - success path (including the reported/returned encounter count and names), and each guard's failure path.
