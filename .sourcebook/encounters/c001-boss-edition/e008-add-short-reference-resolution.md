## Requirements

Implement numbered short-reference resolution for `c001-boss-edition`, after completed `e007-add-boss-candidates`. `docs/boss-edition.md` governs, particularly Canonical names and references, Choosing the next number, Proposed interfaces and implementation surfaces, Compatibility and release plan, and e001 decisions.

- Accept boss `bNNN`, campaign `cNNN`, and qualified encounter `cNNN/eNNN` references wherever an existing object of that domain is selected through current CLI/MCP interfaces. A bare `eNNN` selects an encounter only within an explicitly supplied or active campaign. Full canonical names and legacy unnumbered names continue to work. Resolve using managed records in the current project, never Git branch names, remotes, a search index, or a global registry.
- Short syntax uses lowercase domain prefixes and at least three decimal digits, continuing beyond 999; compare positive numeric IDs as integers so equivalent zero padding cannot choose different records. Numbered canonical names use the corresponding prefix, digits, hyphen, and nonempty slug. Do not impose this format on ordinary canonical names or allocate numbers. Reject malformed qualified refs, wrong-domain refs, invalid path syntax, and unresolved/ambiguous recognized short refs with actionable errors before writes.
- Enumerate both live and archived records for resolution. Unknown refs fail clearly. Duplicate numeric IDs in the requested domain/scope are ambiguous even when split between live and archive or spelled with different padding; never choose the first slug or silently prefer live. The encounter number scope is its resolved campaign, not the project. Duplicate canonical files across live/archive are integrity errors, not two interchangeable copies. Reserved rumors documents never participate.
- Full canonical names with slugs, and legacy names outside recognized short syntax, select that exact canonical record; they remain an inspection/repair route when some numeric IDs collide. A literal historical name that itself looks like a short ref participates alongside numbered matches: if it is the only match it remains usable; if it collides with a numbered match, fail ambiguously rather than silently shadow either record. Document/test this precedence explicitly. Do not invent a rename/escape/backdoor repair operation.
- For an existing encounter target, a qualified ref supplies its campaign when the campaign argument is omitted, including when a different campaign is active or none is active. If an explicit campaign argument is supplied, resolve it independently and reject a mismatch with the qualified ref. Existing unqualified targets keep explicit/active campaign behavior. Enforce all existing campaign mutability, encounter lifecycle, and archive guards after selecting the resolved campaign; qualification cannot bypass them.
- Treat create target names as new literal canonical names, not references to existing records. Boss/campaign/encounter creation keeps existing permissive name validation and uniqueness behavior; no implicit rename, update, replacement, number allocation, or expansion of a short-looking new name into somebody else's record. Encounter creation may use a short ref in its existing-campaign argument; its new encounter name remains literal. Qualified lookup syntax is not a new creation-path syntax.
- Resolve both source and target inputs for boss/encounter dependency operations. Persist full canonical boss names, and full canonical encounter names within their source campaign; encounter campaign metadata remains the full campaign name. Reject cross-campaign encounter prerequisites, including qualified targets pointing elsewhere. Apply duplicate/self/cycle and frozen-state checks after normalization, so mixed short/full spelling cannot bypass them.
- Preserve explicit dependency-removal repair behavior: removing an existing literal canonical edge to a missing target must not require that missing target to resolve again. An ambiguous short ref never authorizes removing an arbitrary edge. Preserve current no-edge/error/idempotence contracts for the respective domains; do not rewrite other dependents or migrate unrelated stored lists.
- Add consistent shared core resolution helpers/results and errors, used by all relevant interfaces. Inventory every shipped boss/campaign/encounter target, campaign selector, dependency input, and applicable-lore encounter selector before implementation. Include read/update/delete where already shipped, lifecycle/archive, encounter region assignment/message/review operations, list/order campaign filters, and prime applicable-lore targeting. Do not add boss deletion or other missing domain operations. Lore/region names, doc names, body/summary/messages, cursor strings, index search phrases, and arbitrary metadata values are not numbered-reference inputs.
- Normalize only external operation inputs and newly written references. Keep stored canonical identities and low-level/internal graph/record lookup explicit: do not reinterpret an existing missing canonical dependency as a short ref, recursively re-resolve persisted names into another record, or make damaged links look repaired. Existing historical records are not renamed or rewritten merely by reading/resolving them. Direct public core entry points used by CLI/MCP must share the contract rather than placing business logic in wrappers.
- Expose resolved canonical identity and a usable short-reference representation through relevant CLI/MCP reads, mutations, and discovery/list results, while retaining existing canonical name/body/status fields and list items. Use additive structured identity metadata instead of replacing list strings or returning the user's shorthand as the canonical name. An unnumbered record or one without an unambiguous short representation has no usable short ref (null with an explicit reason); never publish an ambiguous ref as unique. Encounter output identifies its canonical campaign and qualified short ref, with a contextual bare ref only when its meaning is clear. Document the final common identity shape and where it appears.
- Preserve structured MCP output, literal stored/user text, paging/cursors, get-body truncation, and candidate JSON whole-page bounds. Include added identity metadata in serialized budget calculations before paging/truncation; never append an unbounded reference map to an already budgeted page. Preserve e007 classifications, counts, diagnostics, ordering, and read-only guarantees. Full canonical identities must not be truncated into misleading references; impossible minimum responses may fail explicitly under the established budget policy.
- Resolution is read-only: no record/audit/index/directory writes, number reservation, schema migration, bootstrap, index rebuild, Git branch inspection/switching, or network access. Subsequent authorized operations retain their ordinary side effects and guards, writing canonical values only. Cache only within a request if needed; no persistent mapping that becomes stale across branches or manual edits.
- Update the packaged Workflow Reference Guide, Quickstart, and directly conflicting design wording in the same change for grammar, precedence, archive/ambiguity rules, campaign-context selection, create-vs-lookup inputs, canonical persistence, output identity shape, and error/budget contracts. Preserve deployed skills and unrelated user changes.

Out of scope: numeric allocation/enforcement at creation, Git/remote branch discovery, cross-worktree reservation, automatic collision repair/renaming, promotion/boss_assign_campaign, campaign lifecycle coupling/reactivation/deletion protection, rumors operations, boss prime/search integration or index freshness, planning/campaign skill changes, branching/migration adoption, and new generic metadata mutation endpoints.

## Rationale

Boss storage and candidate discovery are complete, but callers must still supply full names. Shared, unambiguous short references make the next promotion/coupling work consistent across existing interfaces and reduce repeated canonical-name plumbing. Archive-inclusive resolution preserves retained history, while canonical persistence keeps graphs and links independent of how a user spelled an input.

The main risks are selecting the wrong encounter campaign, treating a new name as an existing target, hiding numeric collisions, and reinterpreting damaged stored references. These boundaries must be designed/tested together rather than implemented differently in each wrapper.
