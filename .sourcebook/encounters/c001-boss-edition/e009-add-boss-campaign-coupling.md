## Requirements

Implement boss promotion and campaign lifecycle coupling for `c001-boss-edition`, after completed `e008-add-short-reference-resolution`. `docs/boss-edition.md` governs, especially Promotion contract, Lifecycle and outcome, Reactivation for PR feedback, Dependencies and precedence, Proposed interfaces and implementation surfaces, and accepted e001 decisions.

### Promotion

- Add core/MCP `boss_assign_campaign(name, campaign_name, body)` and `cac boss assign-campaign NAME CAMPAIGN_NAME`. Resolve the existing boss through e008's full/short input boundary; the new campaign name remains literal, permissive canonical input. No numeric allocation/uniqueness gate, branch discovery, or existing-campaign attachment. CLI supports --body/-b, --body-file, and editor fallback seeded with the campaign template; MCP requires body.
- New assignment requires an unarchived, unassigned available boss with satisfied direct prerequisites and no applicable integrity errors. Reuse/refactor e007's core eligibility assessment, never its paged/truncated presentation. Retain exact stored canonical graph/link semantics; missing stored names cannot acquire shorthand meaning.
- Require the campaign name unused in live/archive storage. Preflight safe paths, canonical collisions, malformed/ambiguous links, competing current assignments, and reverse boss claims on that campaign name even if its campaign file is missing. Released abandoned attempts are historical references, not competing current assignments.
- Create exactly one draft campaign with the caller-supplied tactical body and canonical origin `boss`; set the boss's reciprocal canonical `campaign`, retaining available status. Never infer/copy campaign content from boss notes, open a campaign, create encounters, choose another name, or bypass encounter review. Body content follows existing storage semantics, without new fixed sections or text-similarity heuristics.
- Same current, consistent reciprocal assignment is an idempotent read: return existing identities and actual campaign state without writes, restamping, new logs, or body replacement, even if the retry supplies different body text. This includes consistently progressed/completed/archived pairs. Do not rerun initial readiness gates against changed prerequisites. A different target, inconsistent pair, or released/obsolete abandoned attempt fails rather than being reused or retargeted.
- Return both canonical identities, actual campaign status, and an explicit reused indicator with e008-compatible usable short metadata. Avoid embedding both full bodies. Account for minimum identity/output requirements before writes so result validation cannot strand a new pair.

### Lifecycle and history

- Campaign representation/reads/relevant mutation results expose optional canonical origin `boss` without embedding its body, preserving existing fields and bossless legacy behavior. Direct campaign creation stays bossless. Missing/inconsistent origin/current-link diagnostics must be visible for inspection rather than silently looking bossless.
- Complete retains current transition/message/open-encounter guards and appends its postmortem; set its currently assigned boss to vanquished, retaining reciprocal current ownership and frozen design. Opening/pausing/creating campaigns do not vanquish goals.
- Abandon retains current guards/postmortem, makes its currently assigned boss available, and removes that boss's current campaign link. Retain the abandoned campaign's origin reference as history. The released boss may later be promoted into a different new campaign.
- Add core/MCP `campaign_reactivate(name, message)` and `cac campaign reactivate NAME --message TEXT`: unarchived completed -> open for PR feedback, requiring a nonblank attributed reason and the existing single-open-campaign invariant. Preserve earlier completion/postmortem entries, append reactivation history, unlock campaign-body editing while open, and return its consistently linked vanquished boss to available while retaining ownership/design freeze. Completing again appends another closing entry. Completed encounters remain historical; follow-up work uses new encounters. Bossless completed campaigns support reactivation too.
- Reject reactivation from draft/open/paused/abandoned/archived, and coupled mutations with inconsistent reciprocal ownership/lifecycle/archive state. No encounter reopening, archive restoration, generic status setter, or Git-aware merge check. Before-merge feedback remains workflow guidance.
- Archiving a completed linked campaign archives its currently assigned vanquished boss with the campaign and every eligible encounter: preserve statuses, stamp archive/update attributes, and move into established archive layouts. Preserve all-encounters-terminal/collision guards and archived resolution. Standalone boss archive still only accepts unassigned withdrawn goals; linked vanquished archival is internal coupling, not a public backdoor.
- Archiving an abandoned historical campaign archives only that campaign/its eligible encounters. Never mutate its released boss, whether now available, withdrawn, archived, vanquished, or assigned elsewhere. Validate the origin and distinguish legitimate historical release from corrupt purported current ownership; missing/ambiguous origins or inconsistent links require diagnostics before writes. An obsolete campaign cannot release, vanquish, reactivate, or archive another campaign's goal.
- Reject campaign deletion for any origin boss reference, including abandoned/released history and archived linked campaigns. Detect malformed links and reverse current boss claims so a missing campaign-side field cannot bypass protection. Truly bossless campaigns retain existing deletion behavior. No cascading deletion of bosses/encounters/history.
- Validate canonical names/status/archive flags, reciprocity, reverse/competing current claims, and relevant integrity before coupled writes. Never repair links silently or release another campaign's assignment. Align e007 candidate/context diagnostics with successful, released, reactivated, and archived states while preserving its classifications/counts/local-record limits and bounds.
- Coupling changes boss lifecycle/link/archive/update-audit frontmatter only. Preserve raw boss design-body bytes, summary, dependencies, name, creation stamps, and unrelated metadata. Existing assigned/archived design locks remain. No public vanquish/reassignment/generic setter is introduced.

### Recovery and compatibility

- On ordinary in-process failure, coupled writes must finish consistently or restore exact prior record bytes, locations, audit/log content, and ownership. Assignment rollback restores the boss and removes only its newly created campaign, never unrelated/pre-existing records. Archive recovery covers boss, campaign, and every affected encounter.
- Preflight guards and destinations before persistence. Recover logical affected rows changed by existing incremental index synchronization as well as files, without adding boss indexing or invoking/creating an index rebuild. No index is created just for this feature.
- Failed rollback must return an actionable recovery error identifying affected canonical records and residual paths/links; stop without silently retrying, reallocating, forcing cleanup, or claiming success. Preserve unrelated records/index rows. Guarantees cover one local store and ordinary exceptions, not power-loss/crash atomicity, a journal, distributed transactions, or cross-process claims.
- Missing boss storage and legacy bossless campaigns remain supported without inferred goals or retroactive links. Assess schema compatibility explicitly: optional campaign origin is expected additive, but any necessary schema change needs supported migration-guide instructions, never implicit bootstrap migration.
- Ship thin CLI/MCP parity, registration/input-matrix coverage, structured bounded identity/results, literal output, and body-file/editor support. Update canonical workflow/Quickstart and conflicting design wording in the same change. Preserve e008 canonical input/persistence rules and existing get/list/candidate budgets.
- No direct managed-project edits, deployed skill edits, bootstrap/index rebuild, Git/network/branch automation, or number allocation.

Out of scope: rumors; active_boss in prime; boss indexing/index freshness; planner/campaign skill changes/deployment; branching/migration adoption beyond schema assessment; rename/archive restoration; encounter reactivation; public boss deletion/vanquish/reassignment setters; automatic PRs, merges, CI/integration verification, or Git-aware endpoints.

## Rationale

Boss storage, eligibility, and short refs are complete. Promotion now connects aspirational goals to deliberately crafted tactical campaigns; coupling keeps outcomes and current ownership consistent. Abandoned origin references must remain history without controlling a reassigned goal. Recovery must cover the entire affected record cohort and existing index effects, rather than treating a single successful write as a successful operation.
