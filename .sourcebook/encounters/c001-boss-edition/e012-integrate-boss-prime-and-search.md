Before any search returns hits, compare the current indexable source inventory and record contents against the indexed snapshot, including live/archive location and relevant metadata, without using Git or timestamps alone. Detect added/deleted/renamed/moved records and same-size edits with preserved mtimes. Legacy indexes without the supported freshness format require a developer rebuild; never silently trust them. Search/status reads do not mutate sourcebook or index, create missing indexes, migrate old index formats, invoke Git, or rebuild automatically. An unverifiable snapshot or source read failure must not return apparently current hits. This is single-checkout consistency, not a concurrent writer/lock service.
6. Public diagnostics. Core search preserves its list-or-None success contract and raises a dedicated stale-index error carrying actionable bounded diagnostics when freshness cannot be established. CLI search reports the problem with nonzero exit and no hits. MCP search returns an explicit stale result with built=true, stale=true, hits=[], and a diagnostic; successful/missing responses retain existing fields with stale=false. Add freshness reporting to index status, distinguishing missing/fresh/stale, labeling stale counts as indexed snapshot counts. All recovery guidance requires the developer to run cac index rebuild; no rebuild MCP tool. Bound new structured responses and literal CLI output. Oversized requested search responses fail clearly with guidance to lower max_results/snippet_tokens rather than silently skipping hits or changing offset semantics.
7. Direct consumers. Update the existing demo-api search tool to accept boss filtering and report stale search as unavailable with an explicit stale diagnostic and no hits. Preserve its in-process, read-only cac.core usage. Check direct prime consumers for compatibility with the additive context field; adapt only as necessary, without new RAG/UI behavior.

## Rationale

Sessions currently recover tactical campaign context without its originating boss, and search omits boss goals. More seriously, an ignored SQLite index can survive a branch switch and return content from the previous checkout. Prime should expose the selected goal and damaged links; search must distinguish current evidence from stale results.

Content comparison deliberately replaces branch hooks or manual "remember to rebuild" checks. The index remains a derived, developer-maintained cache, separate from sourcebook schema version 1. Incremental updates must not hide unrelated manual/branch changes. The existing scoped Recovery mechanism makes freshness metadata part of lifecycle failure recovery, not just a search wrapper concern.

Depend directly on e009-add-boss-campaign-coupling for links and lifecycle/recovery behavior, and e011-add-campaign-rumors for the nested collection that must remain excluded.
